# MarketDeck public URL inventory contract

Status: design for a future reproducible inventory. No production inventory is generated by this document.

This contract turns [the shared URL policy](url-policy.md) into auditable records. Enumeration is evidence collection, not automatic approval. Candidate URLs come from authoritative manifests, named routes, registries, and real public records; never from guessed ticker lists, scraped-looking string permutations, or multiplying URL patterns by possible query values.

## Record grain and format

The inventory has one record per candidate public representation or owned exclusion/remediation item. The storage format should be UTF-8, machine-readable, deterministic, schema-versioned, and stable under repeated runs against the same deployed SHA and source snapshot. A canonical page has one record with its preferred URL. A class-B representation may have its own record pointing at that canonical. Private examples must be synthetic/redacted; production secrets and private database exports are prohibited.

Recommended primary key: `(canonical_url, repository, route_name, public_record_identifier)`, with a separate immutable run ID in the eventual dataset envelope. `canonical_url` is still populated for B records with the preferred target; for C/D/E records with no legitimate public canonical, it is `null` rather than an invented URL.

## Exact record schema

All fields are required; nullable fields are explicitly noted.

| Field | Type / allowed values | Contract |
| --- | --- | --- |
| `canonical_url` | absolute HTTPS URL or `null` | Preferred `https://marketdeck.in` URL for A/B/F candidate content. Must contain no fragment, credentials, token, or unapproved query. Null for states with no legitimate canonical. |
| `repository` | non-empty string | Verified repository/service owner, for example `marketdeck-web`; do not guess a Git slug. |
| `route_name` | non-empty string | Verified Django named route, static generator owner, or stable source-owner key. Never infer solely from the URL regex. |
| `page_family` | controlled string | Stable family ID from `url-policy.md` plus a readable family name, e.g. `SP-10 fund_detail`. |
| `public_record_identifier` | string or `null` | Source-owned public ID (company key, scheme code, preset key, symbol-universe ID, CoinGecko ID, editorial slug). Null for singleton routes. Never an account ID or share token. |
| `classification` | enum `A`–`F` | Current URL-policy class. F is retained until remediation passes. |
| `intended_indexing_policy` | enum `index`, `noindex`, `non_html`, `not_applicable`, `pending_repair` | Intended search treatment, not observed Google state. |
| `policy_reason` | non-empty string | Concise reason tied to page distinctness, equivalence, utility, privacy, invalidity, or repair. |
| `enumeration_source` | structured string/object | Exact manifest/table/query/registry/named-route source and snapshot/version. It must be reproducible and contain no credentials or private data. |
| `content_eligibility_status` | enum `eligible`, `ineligible`, `pending`, `not_applicable` | Result of page-family gates, independent of HTTP availability. |
| `eligibility_reason` | non-empty string | Evidence for status, including failed minimum-content checks. |
| `expected_http_status` | integer or controlled expression | Normally `200` for eligible A/B landing responses, `301`/`308` for exact aliases, `404`/`410` for E, or explicit `401`/`403` for protected D. If conditional, use a schema-defined status set, not prose ambiguity. |
| `robots_policy` | enum `index_follow`, `noindex_follow`, `noindex_nofollow`, `non_html`, `not_applicable` | Intended HTML/meta or header treatment. `robots.txt` is not access control. |
| `declared_canonical` | absolute URL or `null` | Canonical expected in HTML or HTTP headers. Self for eligible A, preferred target for genuine B, null where equivalence is not asserted. |
| `sitemap_eligible` | boolean | Policy eligibility after content checks. It does not mean membership. |
| `sitemap_membership` | enum `present`, `absent`, `not_applicable`, `unknown` | Observed membership in the deployed sitemap set for the same verification snapshot. |
| `internal_inbound_link` | object | At minimum `{state: present|absent|unknown, source_url: URL|null, discovery_source: string|null}`. Source must be a crawlable public HTML page, not JS-only discovery or a private link. |
| `content_updated_at` | RFC 3339 timestamp/date or `null` | Source truth for substantive update, not inventory run time. Null when unavailable; never fabricate. |
| `deployed_sha` | full Git SHA or deployment digest or `null` | Version verified live. Use the responsible deployment's identifier. Null must generate a verification action. |
| `last_verified_at` | RFC 3339 UTC timestamp or `null` | Time the live status/canonical/content checks were actually performed. |
| `google_inspection_state` | enum `not_checked`, `unknown`, `indexed`, `not_indexed`, `blocked`, `error` | Search Console/inspection evidence only. Never infer `indexed` from a live 200 or sitemap membership. |
| `google_inspection_date` | RFC 3339 date/timestamp or `null` | Required when inspection state came from a real inspection; otherwise null. |
| `next_action` | string or `null` | Owned concrete follow-up. Required for every discrepancy, F record, pending eligibility result, or failed verification. |
| `owner` | non-empty team/person-role string | Accountable owner for the route/data/remediation. Never use an unowned placeholder such as `TBD`; unresolved assignment becomes a governance ticket with an interim owner. |

### Dataset envelope

The future file also needs an envelope outside each record containing `schema_version`, `generated_at`, generator version/SHA, environment, preferred origin, source snapshot identifiers, record count, and a hash of the deterministically ordered records. Sort by `canonical_url` (null last), then `repository`, `route_name`, and `public_record_identifier`. Dates use UTC except source-owned publication dates that are explicitly date-only.

## Enumeration sources

Enumeration adapters are read-only and must emit candidate records plus provenance. Each adapter must distinguish “no rows” from “source failed.” Canonical construction always uses the configured trusted acquisition origin `https://marketdeck.in` plus the verified public mount and a reversed route. It must never trust request `Host`, legacy `SITE_BASE_URL` product subdomains, internal container addresses, or factory-test hostnames. Platform Core is separately rooted at `https://platform.marketdeck.in` and is an exclusion/control adapter only, never an acquisition candidate source.

## Page-family eligibility gates

Adapters apply the detailed rules in `url-policy.md`. At minimum:

- Static/editorial: explicit published status and approval, substantive/source-linked output, unique metadata, and production inclusion.
- Companies: real public company, correct identity, usable entity-specific data, sources/provenance, and no soft-404.
- Statements/peers/Trace Score: differentiated entity-specific usefulness; missing or opaque content remains F rather than being silently collapsed.
- Funds: real scheme code, plan/option identity preserved, usable NAV history and core metadata, public lifecycle state, and an explicit replacement/retirement rule.
- Pagination: integer in range, stable ordering, and non-empty result page. Impossible pages are E.
- Chart instruments: recognized universe membership plus minimum metadata/observation gate; unknown symbols are E.
- F&O and Crypto tools: substantive stable landing; arbitrary result state never inherits landing eligibility.
- Crypto coins: real source ID and sufficient page-family coverage/freshness. Market and fundamentals population counts may differ.
- Commentary: only stable root/market/coverage pages by default; query results require a future explicit curated publishing feature before A.
- Private/token/API/ops: always ineligible for public canonical and sitemap sets.

## Reconciliation sets

All sets contain normalized preferred-origin URLs unless the definition explicitly concerns representations. Normalization removes fragments and disallowed tracking/presentation parameters but must not merge distinct valid pagination or approved finite preset identities.

The pipeline must preserve five independent states: (1) an authoritative candidate record exists, (2) its content eligibility passes, (3) policy approves one canonical URL, (4) that URL is live and technically verified on a deployed revision, and (5) Google inspection reports an indexing state. No later state may be inferred from an earlier one: a database row is not approval, approval is not deployment, a live 200 is not Google indexing, and Google inspection does not rewrite policy.

### `EXPECTED_CANDIDATE_PUBLIC`

All URLs or canonical candidates emitted from authoritative static routes, manifests, real public records, finite registries, and approved public-tool registries before final content approval. It includes pending and F items so hard pages remain visible. It excludes guessed identifiers and private/account/token/API/ops states.

### `APPROVED_ELIGIBLE_CANONICAL`

The subset of expected candidates that is class A, has `content_eligibility_status=eligible`, has exactly one preferred-origin canonical, and has passed privacy and invalid-state checks. This is the denominator for all coverage metrics.

### `SITEMAP_URLS`

Canonical URLs parsed from all deployed public sitemap files for the same release. Only preferred-origin URLs count. Redirects, B representations, query utilities, private routes, errors, and ineligible/F candidates are discrepancies.

### `CRAWLABLE_INTERNAL_LINK_TARGETS`

Normalized URLs targeted by crawlable public HTML anchors from approved roots, hubs, directories, archives, valid pagination, leaderboards, and entity cross-links. A URL discovered only through a form submission, client event, API response, private page, or sitemap is not in this set.

### `LIVE_VERIFIED_CANONICALS`

Approved canonical URLs verified against the deployed SHA with the expected final HTTP status, preferred-origin canonical declaration, index policy, substantive/non-soft-404 response, and correct entity identity. Redirect chains are recorded separately; their targets enter this set only after verification.

## Required reconciliations and ticketing

For every run, compute and retain at least:

- `EXPECTED_CANDIDATE_PUBLIC - APPROVED_ELIGIBLE_CANONICAL`: pending, excluded, or remediation candidates, each with reason and owner.
- `APPROVED_ELIGIBLE_CANONICAL - EXPECTED_CANDIDATE_PUBLIC`: generator/policy provenance defect.
- `APPROVED_ELIGIBLE_CANONICAL - SITEMAP_URLS`: sitemap gap.
- `SITEMAP_URLS - APPROVED_ELIGIBLE_CANONICAL`: sitemap leakage or stale URL.
- `APPROVED_ELIGIBLE_CANONICAL - CRAWLABLE_INTERNAL_LINK_TARGETS`: orphan/discovery gap.
- `CRAWLABLE_INTERNAL_LINK_TARGETS - EXPECTED_CANDIDATE_PUBLIC`: unexpected link, stale route, utility/private leak, or missing enumerator.
- `APPROVED_ELIGIBLE_CANONICAL - LIVE_VERIFIED_CANONICALS`: live technical/content failure or unverified deployment.
- `LIVE_VERIFIED_CANONICALS - APPROVED_ELIGIBLE_CANONICAL`: live policy drift or verifier defect.

Every member of every difference set creates or updates an owned ticket containing the URL/record key, set difference, first/last seen timestamps, deployed SHA, evidence, severity, owner, next action, and resolution link. Suppression requires a documented policy reason, owner, and expiry; a generator must never silently discard a discrepancy.

## Coverage metrics

All three coverage metrics use the same denominator, `|APPROVED_ELIGIBLE_CANONICAL|`. If the denominator is zero, report `not_applicable`, never 100%.

```text
technical_eligibility_coverage =
  |APPROVED_ELIGIBLE_CANONICAL ∩ LIVE_VERIFIED_CANONICALS|
  / |APPROVED_ELIGIBLE_CANONICAL|

sitemap_coverage =
  |APPROVED_ELIGIBLE_CANONICAL ∩ SITEMAP_URLS|
  / |APPROVED_ELIGIBLE_CANONICAL|

internal_discovery_coverage =
  |APPROVED_ELIGIBLE_CANONICAL ∩ CRAWLABLE_INTERNAL_LINK_TARGETS|
  / |APPROVED_ELIGIBLE_CANONICAL|
```

Report numerator, denominator, percentage, run time, and deployed SHA. Alongside coverage, always retain counts by application/page family/class for:

- total expected candidates;
- eligible canonicals;
- pending eligibility;
- F/remediation;
- policy exclusions by reason (B/C/D/E);
- enumeration failures;
- invalid negative fixtures;
- new and resolved reconciliation tickets.

Changing a candidate to an exclusion requires a reviewed policy reason. Coverage must not improve merely because a difficult URL was hidden, an adapter failed, or a source returned zero rows.

## Verification protocol

1. Freeze source revisions and deployed SHAs for every application.
2. Run all enumerators; fail closed on adapter errors while retaining the prior candidates as stale/pending.
3. Normalize only according to the shared URL policy.
4. Apply eligibility gates and preserve exclusions/remediation records.
5. Parse deployed sitemaps and crawl approved public HTML discovery sources.
6. Verify approved canonicals with bounded requests: TLS origin, redirect target, status, content type, robots, declared canonical, entity identity, and soft-404/content checks.
7. Compute sets, metrics, and tickets.
8. Publish the inventory artefact only after privacy scanning and owner review. Inventory publication does not deploy sitemap or runtime changes.

Negative fixtures must include impossible pagination, an unknown company, an invented chart symbol, an unknown fund scheme code, an unknown CoinGecko ID, an expired synthetic share token, malformed query state, and an ephemeral dated Pulse path. Synthetic values must be unmistakably non-production.

## Security and privacy

- Never store real share tokens, portfolio/account identifiers, emails, prompts, upload names, filing contents, or private database rows.
- Never copy credentials, `.env` values, internal API keys, cookies, authorization headers, or service-to-service endpoints into inventory output, logs, tickets, or examples.
- Redact URLs before logging; reject credentials and token-shaped parameters at schema validation.
- Use least-privilege read-only enumeration. Public sitemap generation consumes only the approved public projection, never a raw application table.
- Keep Google inspection credentials and results access-controlled; only the controlled state/date fields enter this inventory.
- Treat a public 200 response as neither authorization nor eligibility.

## Governance and change control

Route owners propose additions or classification changes through review of both this contract and the route-family register. A new A family must define its authoritative enumeration source, eligibility gate, invalid-state response, canonical construction, internal discovery source, sitemap rule, privacy assessment, and accountable owner before implementation.

Schema changes increment `schema_version` and include a migration. Policy changes never rewrite historical run artefacts. Runtime, proxy, robots, sitemap, or deployment changes remain separate tickets and releases.
